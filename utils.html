Encoders that turn text and images into vectors for semantic search, from fast static models to ONNX transformers, plus a fallback that needs no download

Encoders and embeddings

Keyword search finds rows that share words with the query. Semantic search finds rows that mean something close to it, even with no word in common: “car” can find a passage about automobiles. It works by turning each piece of text into an embedding, a fixed-length list of numbers (a vector) placed so that texts with similar meanings sit close together. The model that does this is the encoder. At indexing time the encoder embeds every chunk and the vectors are stored; at query time it embeds the query, and the search returns the chunks whose vectors are nearest.

A query and the documents it searches must be embedded by the same encoder. Vectors from two different models live in unrelated spaces, so comparing them gives meaningless distances without any error. This is why a store records which encoder wrote it (see encoder_id below).

litesearch’s default encoder is static_embedder(), which loads model2vec’s potion-multilingual-128M. A model2vec model is static: it holds one precomputed vector per token and embeds a text by averaging the vectors of its tokens. There is no neural network to run, so it needs no GPU and no ONNX runtime, and it embedded about 8,600 chunks of 500 characters a second on an Apple-silicon Mac. It returns 256-dimensional float32 vectors and covers many scripts, Devanagari included. Index uses it unless you pass another encoder. static_code_embedder() loads potion-code-16M-v2, a model2vec model trained on source code; nothing in litesearch uses it by default, so pass it yourself if you index code. Both functions cache the model per name, so every caller shares one copy. The multilingual model is about 500 MB.

evals/ found that the choice of encoder moves retrieval quality less than chunk size or reranking do. Across four encoders the spread was 0.018 to 0.046 weighted MRR, and the static model won one of the three test corpora outright.

When a transformer is worth the extra time, FastEncode runs one through ONNX Runtime. The dicts in the next cell name models that have been tried with it; each gives the Hugging Face repository, the ONNX file inside it and, where the model needs them, prompt templates. You can pass any of these, any other model2vec model name to static_embedder, or your own object with an .encode method.

FastEncode: transformer models through ONNX

FastEncode runs a text embedding model exported to ONNX, a portable format for neural networks, with ONNX Runtime. It works with most ONNX models that ship a Hugging Face tokenizer. On first use it downloads the model with download_model, which reuses the local Hugging Face cache when the files are already there. The default model is EmbeddingGemma 300M, which gives 768-dimensional vectors.

Each text is split into tokens, cut off at the smaller of the model’s own limit and 512 tokens (max_seq_len replaces the 512), and run through the model. The per-token outputs are averaged into one vector, scaled to length 1 when normalize=True, and returned as float16 by default. Texts are sent in batches of batch_size, parallel runs batches on that many threads, and stream=True returns the batches one by one instead of one joined array. quantize='int8' or 'uint8' writes a smaller quantized copy of the model beside the original on first use and runs that instead.

Many embedding models are trained to see a short prefix that says whether a text is a document or a query, such as search_query: for nomic models. encode_document and encode_query add the prefix from the model’s prompt templates; encode adds none.

FastEncode needs onnxruntime, which is not installed with litesearch (pip install onnxruntime). If the model fails to download or load, the constructor prints the error instead of raising, and every later encode call prints a message and returns None. Check the result before you store it. Qwen embedding models handle their padding token differently and do not work with FastEncode yet.

A function that embeds a list of documents with embedder, using its document prompt when it has one.

doc_encoder and query_encoder give every encoder the same shape: a function that takes a list of strings and returns their vectors. For a FastEncode they call encode_document or encode_query, so the model’s prompts are added. For anything else, a model2vec model or your own object, both call .encode and the two functions behave the same. Index builds both from the encoder you give it.

encoder_id names the model behind an encoder object, for example minishlab/potion-multilingual-128M, with +int8 appended for a quantized FastEncode. A string is returned as it is, and an encoder it cannot name gives ''. Index passes the name to get_store(encoder=...), which records it with the store the first time and raises StoreMismatch if the store is later opened with a different one. Without that check, adding vectors from a second model to an existing store would return wrong neighbours with no error. An empty name never conflicts, so a custom encoder with no name is not checked.

Image encoding

FastEncodeImage embeds images the way FastEncode embeds text, so you can find pictures that look alike: store a vector per image, embed a query image, and search. It takes Pillow images, file paths or image bytes. Each image is converted to RGB, resized to a square of the model’s input size (224 pixels by default) without cropping, normalised with the model’s mean and standard deviation, and run through the ONNX model. Where the model returns one output per image patch, those are averaged into one vector. The default model is nomic-embed-vision v1.5, with 768-dimensional float16 vectors. batch_size, parallel and stream work as in FastEncode, and the method is embed rather than encode. Like FastEncode, it needs onnxruntime and returns None from embed when the model failed to load.

Text and images in one space

To search images with a text query, the text and image vectors have to come from models trained together, so that a caption and its picture land close to each other. There are two ways to get that here.

Some repositories ship a text model and an image model together, such as SigLIP2. FastEncodeMultimodal loads both from one repository and gives you encode_text and encode_image. The default, siglip2_so400m, reads images at 512 pixels and cuts text at 64 tokens.

Other models come as a matched pair in separate repositories. nomic-embed-text v1.5 and nomic-embed-vision v1.5 both produce 768-dimensional vectors in the same space, so load FastEncode(nomic_text_v15) and FastEncodeImage(nomic_vision_v15) separately and compare their vectors directly.

Embedding a PDF without a store

encode_pdf_texts and encode_pdf_images embed a PDF and hand back plain tuples, leaving the table layout to you. Use them when you keep vectors in your own schema instead of a litesearch store.

encode_pdf_texts chunks the PDF with pdf_chunks, or with your own chunk_fn, embeds the chunks with the encoder’s encode_document, and returns (page, chunk_idx, text, embedding) for each, with pages counted from 1. encode_pdf_images saves every PNG and JPEG image in the PDF to a temporary folder, embeds them with an image encoder, and returns (page, image_bytes, embedding). Its pages are counted from 0, unlike encode_pdf_texts. Both return lists.

Embedding with no model

hash_embed makes vectors without any model or download, and gives the same vectors on every run and every machine. It lowercases each text, takes every run of 3 to 5 consecutive characters (character n-grams), hashes each run with CRC32 into one of 256 slots, counts the hits per slot, and scales the result to length 1. Two texts score high when they share many character runs, so the vectors measure spelling, not meaning: “rank fusion” is close to “rank fusions”, but “cat” and “feline” score near zero.

It has two uses. One is matching names, such as people or places, where shared spelling is most of the signal anyway. The other is an index built where no real encoder can be downloaded, for example in a sandbox without network access.
